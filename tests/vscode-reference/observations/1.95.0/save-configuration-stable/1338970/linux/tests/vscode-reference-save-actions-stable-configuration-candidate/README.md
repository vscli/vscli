# Independent stable save-configuration candidate

This candidate preserves the original fourteen case JSON bytes, launch settings order, target text and original target command sequences. It adds two independently bounded public setup barriers before any target gesture. It is a remote-only qualification sandbox: no native policy, old observer, reader, default baseline, required CI guard or historical observation is replaced by these files. The 60 pure Node qualification tests pass locally, including controlled-clock barriers, bounded source reads, bootstrap rejection and retained target failures. Actual three-platform capture and source-matched native adoption remain pending.

The product pin is VS Code 1.95.0 / `912bb683695358a54ae0c670461738984cbb5b95`. `source-sha256.json` admits exactly ten runtime inputs, including the new `save-configuration-ready.cjs`. The worker validates the full inventory and hashes before importing the actual corpus, observer or external editor module, downloading/launching the editor or writing fixtures; the extension suite validates before its corpus/observer/editor imports. The helper itself imports no corpus at bootstrap. Manifest and input reads use regular-file descriptors with pre-read size admission, bounded maximum-plus-one reads and final size/mtime/complete-read consistency before parsing or hashing. Manifest cap is 16384 bytes; each input cap is 1 MiB and aggregate cap is 4 MiB. The corpus is parsed lazily only after full source proof and its separately fixed original case digest. Unknown, missing, traversal and malformed names fail before named input reads. The selected downloaded launcher is hashed in bounded chunks and its actual path, size and hash accompany the pinned product hash. The initial profile/workspace strings and post-editor runtime settings strings have separate immutable receipts; genuine upstream migration is never represented as a harness input change.

## Setup contract

First, `save-participant-readiness-v2` opens only `readiness.ini`, appends an auxiliary marker and performs an explicit public document Save. The exact null-formatter callback must belong to that document object, URI, version and current auxiliary Save, with no cancellation. A direct warm provider call or a callback outside Save cannot authorize readiness. At most sixteen attempts within five seconds are allowed. Every attempt, including misses, and outside-Save callback is retained. All fourteen cases perform this explicit auxiliary Save, including the two afterDelay cases; the target's autoSave setting remains unchanged. The auxiliary provider is disposed before the target opens, returns no edits, and the target disk is asserted unchanged.

Second, `save-configuration-readiness-v1` samples fresh public `getConfiguration` objects for `{uri: main.txt, languageId: plaintext}`. Every sample retains effective values and full inspect values for `editor.codeActionsOnSave`, `editor.formatOnSave`, `files.autoSave` and `files.autoSaveDelay`. Relevant target-scoped configuration events are copied separately and restart the quiet interval. The source-defined layer/effective contract must match repeatedly for at least 250 ms; samples use a fixed 100 ms cadence, a ten-second deadline, at most 128 samples and 128 events. Values are bounded to depth 8, 1024 nodes and 32768 accounted bytes; readiness metadata is bounded to 524288 bytes with error-envelope headroom. Reused public configuration objects are not used for readiness because they can retain an earlier snapshot.

Canonicalization is limited to the pinned object-entry migration: legacy `true` becomes `explicit`, `false` becomes `never`; arrays, order, kinds, absent fields and empty objects stay intact. The effective contract is an explicit declaration for the exact immutable case inventory, rather than a reimplementation of the native settings merger. Inspect expectations preserve the genuine 67ab cohort's paired workspace/folder layers, composite `[plaintext][cpp]` language layers and language-ID order. Current target inputs cover two false booleans; they do not qualify true booleans or boolean language overrides. Declared root/workspace/language values are checked even when a merged effective value could mask them.

Both barriers, command-inventory setup, target open/show and the original one-shot source-provider probe share a fifteen-second deadline. All provider registrations/listeners are retired on setup failure. A final fresh configuration checkpoint must still match before target authorization. Target document text/version/selection/disk are unchanged across the original warm probe. Then each original target command runs once: type, explicit Save or an actual afterDelay acknowledgement, and the original fixed five Undo/five Redo steps. No target output, callback count, durable target bytes or Undo result is used as a readiness predicate. Target commands are counted separately; the setup authorization's zero attempts distinguishes preparation from target execution.

## Raw observations and failure evidence

The original projection shape is retained: fourteen cases and 162 command frames if a complete capture succeeds. Full raw target observations remain authoritative even if unexpected. `configurationDiagnostics` retains the original initial/final snapshots plus every source-provider callback, didSave and relevant configuration event. Target-time canonical checks and a final checkpoint produce a separate `stableConfiguration.valid` flag; a mismatch is retained rather than retried, normalized or silently omitted. After every case and the aggregate raw files have been written, any invalid target-time configuration fails candidate qualification without recapturing targets. A ready quiet interval is not proof that every future migration or main-thread save will succeed, and the explicit auxiliary formatter witness does not expose private participant state.

Before rethrowing a setup/target error, the suite writes compact `<case>-failure.json` plus hashed failure provenance. This retains phase, actual target-command count, setup authorization, both readiness prefixes, original target disk, the complete retained diagnostic prefix and `stable-save-target-prefix-v1`. That target prefix preserves all seen callbacks/saves/change events, completed observations/steps and each issued/pending gesture, including a command that failed before its next observation. Each list is capped at 256 records, complete prefix at 524288 bytes with reserved snapshot/error headroom; current public text/disk each have 65536-byte bounds, 256 selections and a 163840-byte complete current snapshot cap. A secondary disk/getText/snapshot error is recorded separately and never replaces the original target error or previous completed evidence. It claims no successful target qualification. Known-case failure envelopes are bounded to 2 MiB; provenance is bounded to 32768 bytes. The worker's finally block retains declared launch bytes and actual runtime settings receipts on ordinary case failures. Whole-worker termination can leave a partial artifact; logs and every available prefix must still be uploaded. The new runner has its own 300-second supervised process-tree deadline and short macOS `/tmp/vscli-sca-*` sessions. Existing ordinary reference deadlines are unchanged.

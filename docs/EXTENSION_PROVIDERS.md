# Extension language-provider implementation

The optional extension host supplies completion, hover, definitions, references, document formatting, document symbols and signature help to native editor commands. Native editing remains independent of JavaScript. The host wire protocol negotiates this capability and publishes registrations after successful startup. A matching provider from an active owner in the selected ready session takes precedence; when none matches, the existing native LSP route remains available.

The registry implements owner-scoped registrations and result conversion for completion, hover, definitions, references, document formatting, document symbols and signature help. The compatibility values include completion and symbol kinds, MarkdownString, SnippetString, CompletionItem/List, Hover, Location, TextEdit, DocumentSymbol/SymbolInformation, signature values and CancellationTokenSource. Deprecated completion `textEdit` retains its replacement range and takes precedence over `insertText`/`range`, as in the pinned adapter. API numeric kinds are converted from VS Code's zero-based values into the native UI's LSP representation.

The shared native file-language mapping recognizes `.sql` for provider matching; this does not add a SQL syntax grammar or automatically install a SQL server.

Selectors support strings and arrays of language/scheme filters, including `*`, capped at 32 entries. Glob patterns, notebook filters and other selector fields reject explicitly. Completion dispatch supports explicit invocation, debounced identifier typing and registered trigger characters. Trigger contexts translate the LSP invocation/character/incomplete enum into the pinned VS Code API enum; positions and callback ownership retain the same guards. Signature dispatch remains explicit. Completion item resolution and commands, insert/replace range pairs, range/on-type formatting, workspace symbols, code-action providers, diagnostics collections and semantic-token providers remain outstanding. Trusted Markdown and HTML reject; presentation uses the terminal's existing text views.

Provider callbacks receive the current effective configuration before dispatch, including a settings change immediately followed by a native command. Lazy activation publishes providers only after the owner becomes active; failure disposes its registrations while preserving other owners.

The native metadata registry stages whole updates, rejects unknown selected owners, duplicate IDs and malformed filters, and retains the last valid registry on failure. Native selection prefers the highest selector score, then the newest matching registration; multi-provider result aggregation remains outstanding. Registry epochs prevent an earlier selection from surviving a replacement.

Each session allows 128 providers, eight outstanding callbacks and a 1 MiB normalized result. Per-kind result counts and text fields are bounded. Callbacks receive shared document objects, UTF-16 coordinates and cancellation tokens. Document/session/owner/version checks occur before invocation; native text epochs also invalidate tickets and service versions when an edit followed by undo reuses an earlier revision; changed document versions, closed documents and disposed registrations invalidate results. Positions in the current document reject out-of-range coordinates and surrogate splits. Native dispatch independently validates the selected session/provider/registry epoch and mirrored version, plus the workspace, interaction epoch, active pane, every pane selection, and visible/hidden document identities, text epochs, revisions, paths and selections. Suggestion popup navigation and symbol-query typing keep the original editor lease; editor changes invalidate it. Completion uses a nonmodal popup anchored to the active caret, with Tab/Enter acceptance and Escape dismissal. At most 128 models and 16,384 aggregate document/pane selection snapshots are captured. Lengths are checked before cloning; an over-budget request or picker acceptance rejects with a reduce-selections notice while native text and undo remain available. The aggregate counts each retained document and pane view, including duplicated active-view snapshots. Completion commands and snippet completions reject explicitly before mutation.

Formatting and completion edits are staged before mutation. New text normalizes CRLF, CR and LF to the native document's existing EOL convention, then checks the 1 MiB cumulative replacement budget, 4,096-edit limit, strict UTF-16 ranges and overlaps. Files remain unsaved until the user saves; native undo restores the prior text. Invalid additional edits reject the entire completion.

Definitions and references validate target ranges before changing focus or visibility. Existing dirty/shared/hidden models keep their identity and undo, including deleted backing files. Closed files load through one retained background slot, reject missing/nonregular files and use the remaining 4 MiB extension-mirror budget. A three-second native deadline rejects late navigation but retains the worker slot until its actual completion. Closed target content can change independently of the provider; ranges are checked against the newly read text, without claiming an LSP target-version guarantee. Document symbols use the searchable native picker, including hierarchical symbols in untitled buffers; workspace symbol providers and an outline panel remain unsupported.

Callbacks have a five-second deadline. Cancellation and timeout reject the caller promptly. A callback that ignores cancellation retains its slot until it settles, preventing repeated requests from creating unlimited unresolved work. This is a logical bound inside the optional process, not a total extension memory/CPU guarantee. Native transport separately retains up to eight requests/results and uses a six-second reply deadline; host retirement remains the process cleanup mechanism. Cancellation listeners added after cancellation run asynchronously and can be disposed.

`node --test extension-host/providers.test.cjs extension-host/provider-wire.test.cjs` checks selector precedence, receiver/document identity, Unicode/CRLF coordinates, stale replies, owner isolation, disposed providers, cancellation deadlines and retained capacity, result conversions and invalid/oversized result rejection. Wire tests additionally check initial registration snapshots, exact-owner cancellation, removal notifications and document updates during an awaited callback without stalling heartbeat replies. Native integrity tests additionally cover all seven workflows, malformed edits, stale picker acceptance, hidden edits, inactive shared-view selections, registry replacement, callback limits/timeouts and canceled loader retention. A real Unix PTY drives all seven native workflows, original completion/format shortcuts, symbol filtering, Unicode target selection and CRLF save/undo. These synthetic tests do not constitute real-extension workflow qualification or reference-editor differential conformance.

Contract references are pinned to VS Code 1.95.0: [public API declarations](https://github.com/microsoft/vscode/blob/1.95.0/src/vscode-dts/vscode.d.ts), [language selectors](https://github.com/microsoft/vscode/blob/1.95.0/src/vs/editor/common/languageSelector.ts), [provider adapters](https://github.com/microsoft/vscode/blob/1.95.0/src/vs/workbench/api/common/extHostLanguageFeatures.ts) and [cancellation](https://github.com/microsoft/vscode/blob/1.95.0/src/vs/base/common/cancellation.ts). These references guide the implemented subset; full parity is not claimed.

## Named extension qualification

On Linux with Node 26.10.0, unchanged MIT **NPM Intellisense 1.4.5** at commit `bc5521b659b700c8a91cf04897007c611ed9532a` passes native Ctrl+Space package completion using its original deprecated `textEdit`, CRLF/Unicode save, and undo. It additionally passes automatic typing suggestions and Tab acceptance through the native caret popup. This qualifies those completion workflows; its import command and broader package behavior remain unqualified.

The unchanged MIT **SQL Formatter VSCode 4.2.6** at commit `a9988c9e667efca000d17995dae742c9efcdcec8` passes native document formatting on Linux with Node 26.10.0, preserving shared document identity, exact CRLF/Unicode saved bytes and undo. A real terminal test invokes the original Linux formatting shortcut and verifies the exact formatted bytes and restored original bytes after undo/save. Its selection-format command, other dialects and broader package behavior remain unqualified. The CommonJS facade treats the absent `__esModule` marker as undefined so esbuild retains default/named export identity; unsupported real APIs still throw. A real-host bundled-provider regression covers both behaviors.

`tests/extension_provider_corpus_pty.py` is an opt-in qualification script for these externally prepared, compiled trees. Set `VSCLI_NPM_INTELLISENSE` and `VSCLI_SQL_FORMATTER` to their package directories, then run `python3 tests/extension_provider_corpus_pty.py target/debug/vscli`. It verifies package versions, pinned Git HEADs and unchanged tracked source before/after the workflows; it does not download or modify either package. CI prepares both pinned source trees without modifying tracked files: NPM Intellisense uses `npm ci --ignore-scripts` and `npm run compile`; SQL Formatter uses Yarn 1.22.22 with its frozen lockfile and ignored install scripts, then its original `npm run build`. The Linux real-protocol job runs both this terminal script and the two opt-in native integrity tests in `tests/extension_provider_corpus.rs`. Neither workflow establishes reference-editor differential parity or whole-package compatibility.

The native automatic suggestion controller retains one latest queued context and current request, with a six-second lifetime, bounded prefix filtering and strict fresh-reply acceptance. Cached labels shown during typing cannot apply old edits. Scoped quick-suggestion/trigger/Enter settings and unsupported forms are documented in [usage](USAGE.md#automatic-suggestions) and [compatibility](COMPATIBILITY.md).

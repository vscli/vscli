# Extension language-provider implementation

The optional extension host is gaining a language-provider registry. Native editing remains independent of JavaScript. The host wire protocol accepts a negotiated language-provider capability and publishes registrations only after successful startup. Native editor-command dispatch is still being integrated; this foundation does not establish provider support in released builds.

The registry implements owner-scoped registrations and result conversion for completion, hover, definitions, references, document formatting, document symbols and signature help. The compatibility values include completion and symbol kinds, MarkdownString, SnippetString, CompletionItem/List, Hover, Location, TextEdit, DocumentSymbol/SymbolInformation, signature values and CancellationTokenSource. Deprecated completion `textEdit` retains its replacement range and takes precedence over `insertText`/`range`, as in the pinned adapter. API numeric kinds are converted from VS Code's zero-based values into the native UI's LSP representation.

Selectors support strings and arrays of language/scheme filters, including `*`, capped at 32 entries. Glob patterns, notebook filters and other selector fields reject explicitly. The initial dispatch represents an explicit invocation; trigger characters are retained as metadata, without claiming automatic typing-trigger dispatch. Completion item resolution and commands, insert/replace range pairs, range/on-type formatting, workspace symbols, code-action providers, diagnostics collections and semantic-token providers remain outstanding. Trusted Markdown and HTML reject; presentation uses the terminal's existing text views.

The native metadata registry stages whole updates, rejects unknown selected owners, duplicate IDs and malformed filters, and retains the last valid registry on failure. Native selection prefers the highest selector score, then the newest matching registration; multi-provider result aggregation remains outstanding. Registry epochs prevent an earlier selection from surviving a replacement.

Each session allows 128 providers, eight outstanding callbacks and a 1 MiB normalized result. Per-kind result counts and text fields are bounded. Callbacks receive shared document objects, UTF-16 coordinates and cancellation tokens. Document/session/owner/version checks occur before invocation; changed document versions, closed documents and disposed registrations invalidate results. Positions in the current document reject out-of-range coordinates and surrogate splits. Native integration must independently validate the full editor context and every applied edit.

Callbacks have a five-second deadline. Cancellation and timeout reject the caller promptly. A callback that ignores cancellation retains its slot until it settles, preventing repeated requests from creating unlimited unresolved work. This is a logical bound inside the optional process, not a total extension memory/CPU guarantee. Native host retirement remains the process cleanup mechanism. Cancellation listeners added after cancellation run asynchronously and can be disposed.

`node --test extension-host/providers.test.cjs extension-host/provider-wire.test.cjs` checks selector precedence, receiver/document identity, Unicode/CRLF coordinates, stale replies, owner isolation, disposed providers, cancellation deadlines and retained capacity, result conversions and invalid/oversized result rejection. Wire tests additionally check initial registration snapshots, exact-owner cancellation, removal notifications and document updates during an awaited callback without stalling heartbeat replies. These synthetic tests do not constitute real-extension workflow qualification or reference-editor differential conformance.

Contract references are pinned to VS Code 1.95.0: [public API declarations](https://github.com/microsoft/vscode/blob/1.95.0/src/vscode-dts/vscode.d.ts), [language selectors](https://github.com/microsoft/vscode/blob/1.95.0/src/vs/editor/common/languageSelector.ts), [provider adapters](https://github.com/microsoft/vscode/blob/1.95.0/src/vs/workbench/api/common/extHostLanguageFeatures.ts) and [cancellation](https://github.com/microsoft/vscode/blob/1.95.0/src/vs/base/common/cancellation.ts). These references guide the implemented subset; full parity is not claimed.

# Native folding

This candidate adds indentation folding to the native editor without Node or a language server. It is integrated on the main-based display-row foundation. Local qualification and review are described below; protected integration and platform qualification remain pending. This is not full VS Code parity.

Use **Fold**, **Unfold**, **Fold All** and **Unfold All** in the Command Palette. These dispatch the original `editor.fold`, `editor.unfold`, `editor.foldAll` and `editor.unfoldAll` IDs. Linux/Windows use Ctrl+Shift+[ / Ctrl+Shift+]; macOS uses Cmd+Alt+[ / Cmd+Alt+]. The all commands use the original Ctrl+K then Ctrl+0 / Ctrl+J chords (Cmd on macOS). The original `editorTextFocus && foldingEnabled` guard applies. Imported bindings can still replace these rules.

`editor.folding` defaults to true and accepts language overrides. `editor.foldingStrategy` accepts `auto` and `indentation`; both currently use native indentation discovery. A selected caret/range stays visible: collapsed bodies intersecting the full primary or secondary selection interval are conservatively skipped, rather than relocating the selection. Only no-argument command invocations are supported. Clicking a published collapsed gutter chevron unfolds that exact header without changing selection. Expanded gutter markers, recursive/level commands and command arguments are not advertised.

Collapsed views share immutable row preparation with painting, the terminal caret, suggestion placement, mouse hits and vertical/Page movement. Lines retain their physical numbers; source bytes are never deleted or rewritten. CRLF, Unicode grapheme clusters and tab cells use the same prepared scalar/cell descriptors. An eligible split copies fold intent expanded, with fresh private authority, before asynchronous preparation; unfolding one view leaves another view's intent intact. An ordinary shared insertion begins expanded. Disabled, ineligible or empty-intent sources split into ordinary expanded views with no copied fold authority; the folding inventory limit does not reduce native model/group capacities. Tab switches preserve desired folds but discard off-screen prepared maps; a visible view prepares again on the one existing background lane.

Edits, Undo, Redo, selection/reveal, tab-width/settings changes, group ownership changes and stale geometry retire old authority. An invalid source hit is consumed with a repaint notice instead of falling through to physical-line mouse mapping. A logical reveal into a hidden body expands immediately; safe intent may be prepared again asynchronously. Folding changes never create text Undo entries or cancel an authorized save receipt. Automatic refresh publishes silently, preserving a completed save notice; explicit folding commands still announce their result. Unfold All is a checked, source-scan-free clear, including after preparation budget refusal.

## Bounds and failure behavior

One actual worker and one latest intent are retained. Discovery and preparation consume the original owned snapshot and share the original six-second deadline. Logical retirement, cancellation or deadline expiry never releases actual occupancy; result-before-thread-exit keeps the reservation until a positive join. The common shutdown path retires intent and waits up to one second, reporting an unfinished worker rather than claiming it joined.

Discovery admits at most 2 MiB / 100,000 lines / 5,000 regions / depth 256 per source. A view admits 10,000 selections; the model journal holds 256 changes. Folded surfaces admit at most 128 models and 20,000 desired anchors across **all** retained documents and historical views. Above the model limit, refresh, folded movement and frame sealing refuse once without a polling/redraw loop; native expanded editing and Unfold All remain available. Readmission retires old projections before refreshing desired intent. It explicitly retires every off-screen Ready map while preserving desired anchors, so at most four visible maps remain.

Prepared visible windows share an aggregate allowance of 4,096 rows, 262,144 cells and 256 KiB source preparation per frame, including caret-prefix work and conservatively charged failed preparation; any physical line is at most 64 KiB. Remaining allowances, including retained cross-chunk grapheme scratch, are checked before new window allocation. Folded multi-cursor movement stages the whole cohort before publication and charges source and destination line-prefix work against the same 256 KiB gesture allowance. Repeated lines are conservatively charged repeatedly; a large secondary cohort can refuse movement without changing any selection.

The 8 MiB folding metadata envelope accounts retained map/window payload capacities and retained edit-journal capacity once per model, including empty journals and an explicit 4 MiB pending-work reservation. The reservation covers a bounded original snapshot and returned result (each at most 1 MiB), catalogs and concurrently retained controller/phase selection proofs. It remains charged through handoff, returned-result admission and actual join. Independent retained-source accounting conservatively charges full logical Rope byte lengths per ready map and old painted projection, plus one 2 MiB actual/phase snapshot, against an 18 MiB cap. Shared projections and a returned result can be deliberately overcounted. In particular, adoption can refuse while old maps/windows still exist. These are logical source and payload charges, **not** allocator, Rope-node, RSS or process-wide memory measurements. The worker's snapshot and its own text argument share one exact source cohort; a result on that same cohort remains covered by the reservation. App inventory accounting walks all visible and hidden models, not merely the four painted panes.

Budget refusal leaves native editing available in expanded form. A window refusal clears only that view's fold display state; a malformed/stale worker publication preserves text, selections, dirty state and text Undo/Redo. An unchanged failed proof is inert on repeated polling. A new source/view proof or explicit command can attempt a fresh preparation. Ordinary Wrap Off editing remains usable at the native 32 MiB file limit.

Rendering still reads bounded visible lines and styling data; it does not discover folds, flatten the document, replay the journal or wait on a worker. Existing expanded rendering and movement are preserved. This is not a claim that every editor operation is constant-time.

## Local qualification

The final integrated candidate passes 1,122 locked all-target Rust tests across 51 reports (23 opt-in integrations ignored), formatting, strict locked all-target Clippy and both debug and optimized builds. Focused suites include 28 App folding, 21 document folding and 11 display-window tests. They cover unified painting/carets/mouse/movement, generated gutter reveal, Unicode/CRLF exact bytes, selection protection, split independence, settings/view/group ABA, actual worker cancellation and result-before-exit, off-screen map retirement, real authorized Save, shutdown and Undo/Redo. The actual large-frame/held-worker saturation test refuses a copied intent before changing groups, layout or view authority.

All 23 debug terminal reports pass across folding, nested layouts, sticky tabs, source actions on save and C++ syntax stability. All 15 optimized terminal reports pass across folding, nested layouts and sticky tabs. The six folding journeys use an empty executable PATH and missing Node: original shortcuts/movement, all four palette commands, literal edit/Save/Undo/Redo, shared split/independent clear, disabled configuration and an over-budget source. Positive screen/disk receipts and terminal restoration are required. These are Unix PTY results; fresh platform CI remains a merge gate.

The scratch-allocation, retained-journal-capacity and journal-rollover regressions fail with their corresponding production corrections removed. Both 129-model ordinary-split controls fail with the conditional native split route removed, then pass after restoration. The actual save-notice regression failed before automatic refresh became silent. Independent source review found the four budget defects and the unconditional native-split regression; the corrected candidate passed follow-up review without material findings. No local VS Code process was launched.

Original IDs, key contexts and strategy fallback are source-grounded in the [pinned VS Code 1.95.0 folding implementation](https://github.com/microsoft/vscode/blob/912bb683695358a54ae0c670461738984cbb5b95/src/vs/editor/contrib/folding/browser/folding.ts). Native conservative selection protection, source-window bounds, indentation discovery and rejection policy have not been differentially qualified as exact VS Code behavior.

Wrapping, LSP/extension folding providers, language marker/import folding, folding levels/recursive arguments, automatic collapse, session fold mementos and full cursor-relocation parity remain unsupported or unqualified. No folding latency/performance claim is established by this source package.

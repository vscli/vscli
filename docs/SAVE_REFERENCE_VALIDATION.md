# Save reference source and metadata validation

The source-action reference reader admits the original, auxiliary-readiness and
configuration-diagnostic protocols independently. Their raw captures and source
contracts remain historical evidence, including transitional legacy boolean
values. New stable metadata is rejected under every earlier observer contract.

The separate StableV2 reader admits the genuine revision
`133897055d5c524ed1fd0b51866edf95f1faffd8` cohort from
[the complete three-platform archive](../tests/vscode-reference/observations/1.95.0/save-configuration-stable/1338970/README.md).
It verifies all ten frozen runtime inputs, the full 90-file per-platform envelope,
product pin, launch/runtime receipts, case and aggregate digests, fourteen cases
and all 162 frames before checking the setup and target metadata. Raw source,
settings, logs and observed projections are never normalized or rewritten.

Both public setup barriers are independently checked: an exact auxiliary Save
callback and fresh canonical configuration samples with a 250 ms quiet window.
Configuration events and samples retain their own sequence clocks; equal elapsed
timestamps do not invent an order between lists. The reader also correlates each
target-time configuration checkpoint with its actual diagnostic record. Target
commands are issued once; their outcome never authorizes a setup retry.

Regular-file reads admit size before allocation, cap actual descriptor reads and
reject changes during reading. Duplicate JSON keys and unknown protocol fields
refuse. Source budgets are 1 MiB each/4 MiB total with a 16 KiB manifest;
individual evidence is bounded to 2 MiB, aggregate evidence/trace to 64 MiB and
aggregate provenance to 1 MiB. Producer record, text, selection and value budgets
are checked separately. This is offline qualification, not editor input/rendering
work.

Failure-prefix tests are explicitly synthetic, derived only after full genuine
positive admission. They retain original errors, issued/pending gestures and
completed public evidence; they do not claim real failure captures. A truncated
worker artifact cannot certify a successful cohort.

Local qualification passes all 26 ordinary save-reference tests with two optional
artifact tests ignored. The explicit metadata-only artifact test additionally
passes against the separately extracted genuine Linux, macOS and Windows files.
The main-based candidate passes 913 locked all-target Rust tests across 50 reports
with four test threads; 22 optional tests are ignored. Formatting and strict
all-target locked Clippy pass. One borrowed Value comparison was corrected after
initial compilation; no producer, observation or protocol assertion changed.

The earlier 2c readiness and 67ab diagnostics archives retain all 284 original
Git blobs byte-for-byte. Native policy, the default runtime comparison and
ordinary CI still use their previous behavior in this validation change.
Trusted current-head admission, native legacy-boolean normalization and explicit
stable default/CI adoption remain subsequent qualification steps. These results
do not establish full native save or extension parity.

# Native cross-group transfer commands

Implementation candidate: four original keyed commands move the active text editor between native groups. Use Ctrl+Alt+Left/Right on Linux/Windows for Previous/Next Group, and Shift+Alt+1/9 for First/Last Group. On macOS these use Ctrl+Cmd+Left/Right/1/9. The palette exposes `View: Move Editor into Previous/Next/First/Last Group`. Key delivery still depends on the terminal; integrated-terminal forwarding/context policy is a separate qualification boundary.

Previous stops at the first appearance group. Next uses the next existing appearance group, or creates a group after the source at the end. First/Last use existing endpoints. They do not wrap. Same-group endpoint moves preserve preview mode, membership, counters and layout; an endpoint invoked from Explorer can return focus to the editor. No active editor is harmless.

Moves keep the same native document and dirty buffer, carry current primary/secondary selections and scroll projection, and focus the destination. A moved preview becomes committed. Sticky source state follows the move; a duplicate destination tab keeps its existing TabId, becomes committed and retains sticky state if either source or destination was sticky. An unrelated destination preview remains available for later preview replacement. A source group closes when its last membership moves. No dirty prompt or disk write is introduced by the transfer itself.

The engine retains four groups, 128 tabs per group and 512 total memberships. Creating another group at four groups refuses before mutation, even if eventual source collapse would leave four. A full destination accepts duplicate reuse, but refuses a new tab. Clean session persistence retains its separate 32-document limit; restored nested topology/tab ordering and shared views follow the existing schema3 limits.

`workbench.editor.openSideBySideDirection` is validated at user/workspace root scope: `right` (default) or `down`. Highest valid root layer wins; language blocks are ignored and malformed higher layers retain lower valid settings. Changed transfers explicitly refuse valid nonright `workbench.editor.openPositioning` values and `workbench.editor.closeEmptyGroups=false`; the default supported behavior is right-of-active insertion and source empty-group collapse. These settings do not implement their general workbench behavior for other opening/closing commands. Imported settings bytes remain unchanged.

Groups, layout and view projection prepare before publication. Layout creation anchors to the still-present source before source collapse. Failed capacity/proof/settings/layout/view preparation retains the original models, groups, selections, history and files. Source pointer maps and language widget ownership retire after a changed transfer.

Approved saves retain their captured Document identity. Save/Save As can finish after transfer or source-group collapse, publish the original snapshot and baseline, and preserve newer unsaved text. A Save→Close for the removed source Membership cannot close its new/reused destination. Moving another tab preserves an independently approved original close while retiring only the remaining captured batch. A stale unapproved dirty-close modal retires without discarding unsaved text or canceling accepted save receipts.

Text Undo/Redo and shared document identity remain native. Source snippet/auto-pair/cursor-history ownership retires; the transfer projection does not copy those private sessions into the destination. Fresh private view lifetimes and checked destination generations prevent historical Undo snapshots from reviving retired generated brackets or snippet sessions, including a previously closed target view. Returning focus through a same-group First/Last endpoint dismisses a live Breadcrumbs picker while preserving group identities and pending Redo. Exact active-caret Undo behavior for an edit originally owned by a removed source view has not been compared to upstream. It is not a claim of whole workbench transfer parity.

Directional `moveEditorToLeft/Right/Above/BelowGroup` wrappers remain unregistered: original missing-neighbor behavior creates groups and needs a complete creation/order transaction rather than an existing-only alias. Copy wrappers, drag-and-drop, multi-selected editors, arbitrary `moveActiveEditor` arguments, auxiliary windows, editor-specific vetoes, retained empty groups and nondefault insertion policy remain outside this slice.

The historical Windows CI save wait remains undiagnosed. Bounded
[test-only save-worker progress diagnostics](SAVE_WORKER_DIAGNOSTICS.md) now
distinguish actual authorization receipt, persistence calls, cleanup, terminal
send and thread completion without changing production behavior or deadlines.
An isolated local pass does not qualify the Windows full-workload failure.

Local qualification passes nine App integrity cases, two settings cases, one original platform-key case and a real symbol-provider Breadcrumbs endpoint regression. The locked all-target Rust suite passes 1,047 tests across 51 reports with four test threads; 20 opt-in tests are ignored. Formatting and strict all-target locked Clippy pass. Four new native PTY reports run across six isolated sessions, checking original keys/palette commands, exact Unicode/CRLF Save/Undo/Redo, clean session restart, sticky deduplication, unrelated preview ownership, right/down topology and inert policy/capacity refusal. Eight relevant Unix PTY scripts pass 39 reports in total: transfer, group tabs, nested layout, sticky tabs, reordering, directional focus, preview tabs and smart typing. The separately tested foundation includes 57 editor-group tests (thirteen transfer cases) and six Document integrity tests. Fresh platform CI remains a separate gate. No new local VS Code instance/capture was used; original command semantics are sourced from pinned 1.95.0 code/inventories, rather than a newly observed transfer trace.
